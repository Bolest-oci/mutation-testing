# Use Case: 05.2 - Propose Test Fixes or Additions

## Description
This use case describes how the agent proposes improvements to existing tests
or suggests new tests to kill surviving mutants.  
The system can execute the analysis in **Default**, **Advanced**, or **Custom** mode depending on user choice.

## Actor
RooCode Agent

## Preconditions
- Use Case 05.1 has been completed.
- Surviving mutants and their causes are known.

## Flow

1. **Select Analysis Flow**
   - Agent asks the user which flow to execute:
     - **Default** → standard step-by-step analysis of one mutant (minimal approach).
     - **Advanced** → enhanced, multi-step analysis with automation and prioritization.
     - **Custom** → user-provided flow (Markdown or structured input). The agent loads and validates it.

### Default Flow

2. **Select Target Mutant**
   - Agent selects a surviving mutant for analysis.

3. **Inspect Existing Tests**
   - Agent locates relevant test files.
   - Agent reviews test structure, assertions, and input data.

4. **Generate Fix Strategy**
   - Agent chooses one of the following:
     - Strengthen existing assertions
     - Add missing assertions
     - Extend parameterization
     - Add edge case coverage
     - Correct flawed test logic

5. **Draft Test Changes**
   - Agent proposes concrete code changes.
   - Changes are minimal and aligned with project testing style.

6. **Explain Rationale**
   - Agent explains why the change should kill the mutant.

### Advanced Flow (Actionable)

2a. **Select Target Mutants**
   - Filter mutants by status:
       pending or proposed → include
       fixed or ignored → skip
   - Prioritize remaining mutants based on coverage gaps, likelihood to survive, or severity.

3a. **Inspect Existing Tests with AI/Heuristics**
   - Agent analyzes test files for:
     - Missing assertions
     - Edge case coverage
     - Overly permissive or flawed logic
   - Agent assigns a **risk score** to each test based on how likely it is to fail to kill the mutant.

4a. **Generate Fix Strategies**
   - For each mutant, agent proposes one or more strategies:
     - Strengthen or add assertions
     - Extend parameterization
     - Add edge case coverage
     - Propose integration or system-level tests
   - Agent selects the **optimal strategy** based on risk scores and impact.

5a. **Draft Test Changes**
   - Agent creates concrete code modifications for each proposed strategy.
   - Changes are minimal, aligned with project style, and grouped by mutant.

6a. **Generate Reports**
   - Agent outputs:
     - Summary tables of mutants, affected tests, and proposed changes
     - Detailed rationale for each change
     - Optional machine-readable format (JSON, CSV) for integration with CI/CD pipelines

7a. **Optional Post-Actions**
   - Agent may:
     - Draft PRs in the repository
     - Notify team members of proposed changes
     - Track which mutants are resolved or pending

8a. **Explain Rationale**
   - Agent provides a rationale summary for all changes, ensuring clarity for review.

### Custom Flow

2b. **Execute Custom Proposal Flow**
   - Agent executes the user-provided flow.
   - Custom flow may redefine analysis steps, output format, or analysis logic.
   - If essential outputs (e.g., rationale or summary) are missing, the agent ensures **Explain Rationale** is produced.

## Postconditions
- Proposed test modifications are ready for user review.
- No production code is modified in this use case.
- Any custom or advanced flow output is included as supplemental information.
