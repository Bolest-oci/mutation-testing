# Use Case: 05.3 - Apply Test Fixes

## Description
This use case describes how approved test fixes are applied to the codebase.  
The system applies fixes safely, verifies tests, updates mutant tracking, and optionally generates reports.

## Actor
RooCode Agent

## Preconditions
- Test fix proposals have been reviewed and approved by the user.
- The agent has write access to test files.
- (Optional) A mutant tracking file exists to record which mutants have been fixed.

## Flow

1. **Backup Test Files**
   - Agent creates a backup of all test files that will be modified.

2. **Apply Approved Fixes**
   - Agent updates the test files according to the approved proposals.
   - Changes respect existing test conventions and formatting.

3. **Verify Changes**
   - Agent runs only the affected tests first.
   - Agent then runs the full test suite.
   - If any test fails:
     - Agent restores from backup.
     - Logs the failure for user review.

4. **Update Mutant Tracking**
   - Agent marks each mutant associated with the applied fixes as `fixed` in the TXT tracking file:
     ```
     mutant_id | fixed | timestamp | test_file
     ```
   - This ensures already-fixed mutants are skipped in future runs.

5. **Commit Test Changes**
   - Agent stages modified test files:
     ```bash
     git add tests/
     ```
   - Agent commits changes:
     ```bash
     git commit -m "test: Apply approved fixes from mutation analysis"
     ```

6. **Optional Post-Actions**
   - Agent may:
     - Generate a summary report of applied fixes.
     - Create a draft PR in the repository.
     - Notify team members of applied changes.

7. **Explain Rationale**
   - Agent documents the rationale for each applied fix in the report or commit message.

## Postconditions
- Tests are updated and passing.
- Changes are committed to the mutation-testing branch.
- Mutant tracking file is updated to prevent reapplying fixes.
- Optional reports summarize applied changes and mutants resolved.
