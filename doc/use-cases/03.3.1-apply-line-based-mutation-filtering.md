# Use Case: 03.3.2 – Apply Line-Based Mutation Filtering

## Description
This use case describes how mutation testing is restricted to only those lines of code that were recently changed, by explicitly applying Cosmic Ray’s git-based mutation filtering mechanism.

## Actor
RooCode Agent

## Preconditions
- A baseline branch for comparison is available.
- Relevant code changes and line ranges have already been identified.
- A Cosmic Ray configuration file exists.
- A Cosmic Ray mutation database file exists.

## Flow
1. Agent locates the Cosmic Ray configuration file and the associated mutation database file.
2. Agent ensures that the Cosmic Ray configuration file contains the following section:

   [cosmic-ray.filters.git-filter]
   branch = "<branch_to_compare>"

   - If the section exists, agent updates the branch value.
   - If the section does not exist, agent creates the section with the specified branch.

3. Agent executes the Cosmic Ray git-based filtering command on the mutation database:
   
   cr-filter-git <database_file>

4. By executing the filtering command, agent ensures that all mutations outside the changed line ranges are marked as skipped and removed from the active mutation execution list.
5. If execution of the git-based filtering command fails, agent treats this as a blocking error and reports that line-based mutation filtering cannot proceed.

## Verification
- The mutation database reflects that mutations outside changed line ranges are marked as skipped.
- Only mutations associated with recently changed lines remain eligible for execution.

## Postconditions
- Mutation testing is restricted exclusively to changed line ranges.
- The mutation database is prepared for targeted mutation test execution.
