# Use Case: 03.1 – Apply Line-Based Mutation Filtering

## Description
This use case describes how mutation testing is restricted to only those parts of the codebase that were recently changed. The agent identifies changed files and exact line ranges using version control and applies Cosmic Ray’s git-based mutation filtering mechanism to skip all mutations outside these ranges.

## Actor
RooCode Agent

## Preconditions
- A baseline branch or commit for comparison is available.
- The project repository is under version control.
- A Cosmic Ray configuration file exists.
- A Cosmic Ray mutation database file exists.

## Flow
1. Agent executes a version control diff against the baseline branch.
2. Agent identifies modified source files together with exact changed line ranges, while ignoring whitespace-only changes and non-code files.
3. Agent ensures that the Cosmic Ray configuration file contains the following section:

   [cosmic-ray.filters.git-filter]  
   branch = "<branch_to_compare>"

   - If the section exists, the agent updates the branch value.
   - If the section does not exist, the agent creates the section with the specified branch.

4. Agent executes the git-based mutation filtering command on the mutation database:

   cr-filter-git <database_file>

5. By executing the command, all mutation jobs whose line ranges do not intersect the changed lines are marked as skipped directly in the mutation database.
6. The remaining set of candidate files and line ranges is passed to subsequent mutation filtering steps.
7. If the git-based filtering command fails, the agent treats this as a blocking error and terminates the use case.

## Verification
- The mutation database contains skipped entries for all mutation jobs outside the changed line ranges.
- Only mutation jobs associated with recently changed lines remain eligible for execution.

## Postconditions
- Mutation testing is restricted exclusively to recently changed line ranges.
- The mutation database is prepared for further targeted filtering steps.
