# Use Case: 03.3 – Select Relevant Mutation Operators

## Description
This use case describes how mutation operators are selectively enabled or disabled based on recent code changes, using Cosmic Ray tooling, in order to avoid generating irrelevant or equivalent mutants.

## Actor
RooCode Agent

## Preconditions
- A baseline branch for comparison is available.
- A Cosmic Ray configuration file exists.
- A Cosmic Ray mutation database file exists.
- Relevant code changes have already been identified.

## Flow
1. Agent locates the Cosmic Ray configuration file used for mutation testing.
2. Agent ensures that the configuration file contains the following section:

   [cosmic-ray.filters.operators-filter]
   exclude-operators = []

   - If the section exists, agent uses it.
   - If the section is missing, agent creates it with an empty `exclude-operators` list.

3. Agent retrieves the complete list of available mutation operators by executing the Cosmic Ray command that lists supported operators.
4. If retrieving the operator list fails, agent treats this as a blocking error and reports that mutation operator selection cannot proceed.
5. Agent executes a version control diff between the baseline branch and the current state to obtain recent code changes.
6. Agent analyzes the detected code changes to determine which categories of mutation operators are applicable.
7. Agent determines which mutation operators are not relevant to the detected changes.
8. Agent updates the `exclude-operators` list in the Cosmic Ray configuration to explicitly exclude all non-relevant operators.
9. Agent applies the updated operator filtering by executing the Cosmic Ray operator filter command on the mutation database:

   cr-filter-operators <database_file> <config_file>

10. If execution of the operator filtering command fails, agent treats this as a blocking error and reports that mutation operator filtering cannot proceed.

## Verification
- The Cosmic Ray configuration contains an updated `exclude-operators` list reflecting excluded operators.
- The mutation database reflects that excluded operators are no longer active.
- At least one mutation operator remains enabled after filtering.

## Postconditions
- Mutation operator selection is aligned with the nature of recent code changes.
- The Cosmic Ray mutation database reflects the filtered operator set.
- The configuration and database are ready for targeted mutation testing execution.
