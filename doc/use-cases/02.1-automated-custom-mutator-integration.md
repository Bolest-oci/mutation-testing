# Use Case: 02.1 - Automated custom mutator integration and execution

## Description
This use case automates the process of setting up a virtual environment, installing dependencies, integrating a custom mutator, running mutation testing with Cosmic Ray, and generating an HTML report.

## Actor
RooCode Agent

## Preconditions
- Python 3.x is installed and available in the system's PATH.
- The custom mutator source code is available.
- A `cosmic-ray.toml` configuration file exists. If it does not, it will be created. Note that the path to this file may vary.

## Flow
1.  **Set Terminal for UTF-8 (Optional):**
    - To ensure proper handling of UTF-8 characters, you can set the `PYTHONUTF8` environment variable.
    - ```bash
      export PYTHONUTF8=1
      ```

2.  **Create and Activate Virtual Environment:**
    - Create a new virtual environment.
    - ```bash
      python -m venv .venv
      ```
    - Activate the virtual environment. Note that the activation command differs between operating systems.
    - **On Windows (Command Prompt or PowerShell):**
    - ```bash
      .\.venv\Scripts\activate
      ```
    - **On macOS and Linux:**
    - ```bash
      source .venv/bin/activate
      ```
    - **Verification:** The shell prompt should indicate that the virtual environment is active.

3.  **Install Dependencies:**
    - Install Cosmic Ray.
    - ```bash
      pip install cosmic-ray
      ```
    - Install the custom mutator in editable mode.
    - ```bash
      pip install -e <path/to/your/custom-mutator>
      ```

4.  **Configure Cosmic Ray to Use Custom Mutator:**
    - Locate your `cosmic-ray.toml` file. If it doesn't exist, create it.
    - Add or modify the `[cosmic-ray.filters.operators-filter]` section to specify your custom mutator. The `exclude-operators` key should contain a list of regular expressions. To use *only* your custom mutator, you can use a negative lookahead.
    - ```toml
      [cosmic-ray.filters.operators-filter]
      exclude-operators = [
        "^(?!<module_name>/<operator_key>).*$",
      ]
      ```
    - Replace `<module_name>` and `<operator_key>` with the appropriate values for your mutator.

5.  **Run Mutation Testing:**
    - Initialize a new Cosmic Ray session, making sure to provide the correct path to your configuration file.
    - ```bash
      cosmic-ray init <path/to/cosmic-ray.toml> session.sqlite --force
      ```
    - Apply the operator filter to the session.
    - ```bash
      cr-filter-operators session.sqlite <path/to/cosmic-ray.toml>
      ```
    - Execute the mutation testing session.
    - ```bash
      cosmic-ray exec <path/to/cosmic-ray.toml> session.sqlite
      ```

6.  **Generate HTML Report:**
    - Generate an HTML report from the session data.
    - ```bash
      cr-html session.sqlite > <report-name>.html
      ```
    - **Verification:** An HTML file with the name you specified should be created.

7.  **Deactivate Virtual Environment:**
    - Deactivate the virtual environment.
    - ```bash
      deactivate
      ```

## Postconditions
- A virtual environment is created and dependencies are installed.
- The `cosmic-ray.toml` file is configured to use the custom mutator.
- Mutation testing has been executed, and the results are stored in `session.sqlite`.
- An HTML report is generated.
- The virtual environment is deactivated.

## Troubleshooting

### `cosmic-ray.toml` Not Found
- **Problem:** The `cosmic-ray init` command fails because it cannot find the `cosmic-ray.toml` file.
- **Solution:** Ensure you are providing the correct path to your `cosmic-ray.toml` file. Use the `search_files` tool if you are unsure of its location. Note that the file may be named `cosmicray.toml` (without a hyphen).

### `cosmic-ray init` fails with "Could not find module path"
-   **Problem:** When running `cosmic-ray init`, you might encounter an error like `Could not find module path src/cosmic_ray`.
-   **Cause:** This happens if the `module-path` in your `cosmic-ray.toml` is a relative path that's incorrect from the project's root directory (where the command is being executed). Cosmic Ray needs to know where to find the source code to mutate.
-   **Solution:** Ensure that the `module-path` and any paths in `excluded-modules` in your `cosmic-ray.toml` file are correct relative to the root of the project.

### Operator provider load failure warnings
-   **Problem:** You may see warnings like `Operator provider load failure...` for operators that are not part of your current project.
-   **Cause:** These warnings indicate that Cosmic Ray has detected operator plugins that were installed in the Python environment but are no longer present or relevant.
-   **Solution:** These warnings can generally be ignored. If you wish to remove them, you can uninstall the unnecessary operator packages using `pip uninstall -y <operator-package-name>`.

### Incorrect Operator Name in Configuration
- **Problem:** Cosmic Ray fails to apply the custom mutator and runs with the default set of operators.
- **Cause:** The operator name in the `[cosmic-ray.filters.operators-filter]` section of the `cosmic-ray.toml` is incorrect. The format is `"<module_name>/<operator_key>"`.
- **Solution:**
    1.  **Identify the module name:** This is the name of the directory containing the custom mutator's `setup.py` file.
    2.  **Identify the operator key:** This is the key in the `_operators` dictionary within the mutator's `provider.py` file.
    3.  **Combine them in `cosmic-ray.toml`:** The `exclude-operators` value should be a list containing a string with a regex, like this: `exclude-operators = ["^(?!<module_name>/<operator_key>).*$"]`.

### `deactivate` command not found
- **Problem:** The `deactivate` command fails with an error indicating it is not recognized.
- **Cause:** This can happen in non-interactive shells or if each command is run in a separate shell instance, as the virtual environment's activation is not persisted.
- **Solution:** In automated scripts, it's often not necessary to explicitly deactivate the environment, as it will be inactive in the next shell session. The primary goal is to use the virtual environment for the installation and execution steps, which will have already completed.
