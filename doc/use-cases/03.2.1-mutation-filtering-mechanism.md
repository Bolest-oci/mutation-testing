# Use Case: 03.2.1 – Exclude Mutation Jobs via Database Filtering

## Description
This use case describes how mutation jobs are explicitly excluded from execution based on quality gate decisions by marking them as skipped in the Cosmic Ray mutation database.  
It is used by quality-related steps such as linting and coverage evaluation to remove mutation targets deemed invalid or irrelevant.

## Actor
RooCode Agent

## Preconditions
- A Cosmic Ray mutation database file exists and has been initialized.
- Relevant files and line ranges have been identified.
- One or more quality gate checks (e.g. linting, coverage) have produced exclusion decisions.

## Flow
1. Agent receives a set of exclusion inputs produced by a quality gate, such as:
   - source file paths,
   - exact line ranges,
   - or individual mutation identifiers.
2. Agent opens the Cosmic Ray mutation database (SQLite).
3. Agent queries the `mutation_specs` table to identify all mutation jobs whose:
   - `module_path` matches the excluded files, and
   - mutation line ranges intersect the excluded line ranges.
4. For each identified mutation job, agent inserts or updates an entry in the `work_results` table with:
   - `job_id` set to the mutation job identifier,
   - `worker_outcome` set to `SKIPPED`,
   - `output` describing the exclusion reason (e.g. "Filtered by lint", "Filtered by coverage"),
   - `test_outcome` set to NULL,
   - `diff` set to NULL.
5. Agent does not remove any mutation definitions from the database; only the execution state is updated.
6. The updated mutation database is persisted for subsequent mutation testing steps.

## Verification
- Mutation jobs corresponding to excluded files or line ranges have entries in `work_results` with `worker_outcome = SKIPPED`.
- Mutation jobs not affected by quality gates remain eligible for execution.

## Postconditions
- Mutation jobs deemed invalid by quality gates are excluded from execution.
- The mutation database accurately reflects quality-based filtering decisions.
